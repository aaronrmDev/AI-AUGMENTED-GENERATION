# ADR-0003: Standard Attention + Cache Optimization (Path A)

Status: Accepted

## Context

The CAG layer's value proposition rests on manipulating the KV cache directly — precomputing and reusing prefixes, packing entries into paged blocks, evicting low-value tokens, compressing what remains, and speculatively decoding ahead of it. All of that machinery assumes a standard (softmax) attention mechanism, which is what produces a per-token KV cache in the first place. Alternative attention architectures such as Linear Attention and State Space Models (Mamba) take a different approach: they replace the growing per-token cache with a fixed-size recurrent or hidden state, which is precisely what makes them attractive for ultra-long contexts but also means there usually is no conventional KV cache for cache-optimization techniques to act on. The project needed to decide, up front, which of these two architectural paths to build around, since committing to both at once would mean maintaining two incompatible sets of serving infrastructure.

## Decision

This project uses standard attention with cache optimization (Path A) and does not use alternative attention mechanisms (Linear Attention, Mamba, and similar). This is a deliberate architectural choice, not an oversight: it is what allows prefix caching, PagedAttention — which divides the KV cache into fixed-size blocks the way an operating system pages memory, rather than requiring one contiguous slab per sequence — and the rest of the CAG stack described in this project's architecture to function as designed.

Four of this project's eight CAG techniques break under alternative attention, because each one depends on manipulating a per-token KV cache that alternative-attention architectures simply don't produce: KV Cache Eviction has no individual token entries left to select for removal, KV Cache Compression has no per-token cache left to quantize or shrink, PagedAttention has no KV blocks left to allocate or share, and Speculative Decoding's verification step assumes standard attention's token-by-token cache dynamics that alternative attention doesn't have. The other four survive the switch intact, because they operate above the attention mechanism itself — at the scheduling, session, or storage-tiering level — rather than reaching into per-token cache internals: Prefix Caching stays useful for initializing shared state, even if less impactful; Hybrid Offloading becomes optional rather than necessary, since the recurrent state is already small; Multi-Turn Caching is conceptually replaced by the architecture's own recurrent state, though not in conflict with it; and Cache-Aware Batching still applies, just with different batching logic rather than being blocked outright. In short, alternative attention doesn't conflict with cache-based methods as a category — only with the four that reach into a per-token KV cache that, on this architecture, was never there to reach.

## Consequences

Committing to Path A means the project can build directly on vLLM-style serving infrastructure — prefix caching, PagedAttention, eviction, compression, and speculative decoding all become available and mutually reinforcing, as described in the CAG ecosystem sections of this project's architecture. It also means the project forgoes the O(N) or O(N log N) complexity advantages and effectively unbounded context length that alternative attention architectures offer, along with their smaller memory footprint at extreme context sizes. Should a future requirement demand ultra-long contexts beyond what cache optimization on standard attention can economically support, revisiting this decision would mean a genuine architectural fork rather than an incremental change, since the two paths are not designed to run as a single unified stack.
