# CAG Batch B: KV Cache Compression — Live Measurement Report

**Scope:** #31 (story), #97 (KIVI), #99 (KVQuant), #100 (PALU), #101 (MiniCache), #103 (ShadowKV) — five distinct compression algorithms. See `docs/superpowers/specs/2026-08-29-cag-kv-cache-compression-design.md` for the design and why this batch (not Prefix Caching) followed Batch A in the CPU/Ollama-feasible sequence: `docs/testing/TESTING.md` commits prefix caching specifically to validation against real vLLM, because the claim under test there is the fallback cascade's unconditional trust in a cache hit — a serving-engine behavior no stand-in can honestly demonstrate. Compression's own correctness question (does reducing precision, dimensionality, or cross-layer redundancy preserve enough signal for correct generation) carries no such commitment, and is honestly measurable against a real model with no GPU or vLLM.

## What CAG.md asks for, and what this batch built

Five methods, all shrinking an already-evicted KV cache's remaining footprint by precision, dimensionality, or redundancy rather than discarding tokens outright: KIVI and KVQuant (quantization), PALU (low-rank projection), MiniCache (cross-layer redundancy), and ShadowKV (a hybrid stacking several of the above). Four compress a single layer's tensor in isolation; MiniCache is structurally different — it merges two adjacent layers into one shared representation, which needed its own port (`CrossLayerKVCompressor`) rather than being forced into the other four's single-tensor shape, the same reasoning MAG used to keep `Archive` outside `GateMemories`'s default composition.

## KIVI — per-channel quantization with residuals

Real per-channel quantization: tokens grouped in blocks of `group_size`, every full group quantized per channel with its own scale and zero-point, a trailing partial group kept as an exact full-precision residual rather than quantized with a smaller group. Measured ~4x compression matching CAG.md's stated figure.

Two review rounds caught real gaps in how this was tested, not in the algorithm itself. Round one found the original fixture couldn't distinguish correct per-channel quantization from a hypothetical per-token axis-swap bug — both measured statistically indistinguishable error (0.1667 vs 0.1653) on data where every channel shared the same value range. Fixed with a fixture giving each channel a distinctly different amplitude, which widened the gap to over 3x (0.317 buggy vs 0.096 correct). Round two then found something sharper: a *hybrid* bug — scale computed correctly per channel, but zero-point accidentally bound to one group-wide value — passes every reconstruction-error test in the file, including the new one, no matter how the fixture is tuned. This isn't a fixture problem; it's provable: `decompress()` reconstructs as `zero_point + quantized_index * scale` with `quantized_index` stored as an unclipped integer, so reconstruction error is bounded by `scale / 2` regardless of the zero-point's own origin. No error-tolerance assertion could ever catch this bug class. The fix was a genuinely different kind of test — asserting directly on the `zero_points` payload's own structure (a correct implementation reports distinctly different values per channel; the bug reports one value repeated across all of them) — verified against the exact mutation the review planted.

## KVQuant — non-uniform quantization with outlier isolation

Quantile-based (equal-population) bucket boundaries computed from each channel's own order statistics, plus explicit per-channel outlier detection and full-precision storage, so a single extreme value no longer stretches the quantized range for everyone else. Measured exactly 8.0x at 2 bits with zero outliers present, matching CAG.md's "up to 8x" ceiling — reaching it specifically requires a lower bit width than KIVI's typical 4-bit baseline, since KVQuant's real edge over KIVI at *equal* bit width is fidelity (confirmed head-to-head: ~10.5x lower reconstruction error on data with injected outliers), not a free ratio improvement.

Hit the identical axis-fidelity gap KIVI's own test did, for a related but distinct reason: at bits=4 (16 quantile buckets) over only 6 channels per row, per-row bucketing trivially gives every value its own bucket regardless of axis — the buggy version measured exactly 0.0 error, passing *more* comfortably than the correct implementation. Fixed by widening the channel count past the bucket count (32 channels, 16 buckets), which restored a real, measurable gap (~3.68 buggy vs ~1.80 correct).

## PALU — SVD-based low-rank projection

Real SVD truncation via `numpy.linalg.svd`: decomposes the KV tensor, keeps the top-k singular values/vectors, caches the compact latent `H = U_k @ diag(S_k)` and reconstruction factor `B = V_k^T`. The strongest correctness test of any compressor in this batch derives its own tolerance from the Eckart-Young theorem — the mathematically provable lower bound on any rank-k approximation's error, computed independently in the test itself — rather than an arbitrary number, and a second test confirms near-machine-precision reconstruction on data that is genuinely low-rank by construction.

The one real bug this batch's review caught in an actual measurement (not just a test gap): raising PALU's rank from 8 to 32 for the full-layer integration test, intending to "match" the tensor's larger channel count, instead silently clamped to `effective_rank = min(rank, num_tokens, num_channels)` — and the real prompt tokenizes to exactly 15 tokens, so rank 32 clamped to 15, full rank for that sequence length. Full-rank SVD is mathematically lossless, so the integration test's "compression" for both PALU and ShadowKV (which composes PALU directly) had silently become an exact round-trip, measuring 0.0000 diff — not because the algorithm preserved fidelity well, but because no truncation was actually happening. The binding ceiling on SVD rank is sequence length, not channel count; reverting to rank=8 (genuinely below 15 tokens) restored real, honest lossy compression, with real non-zero measured diffs (0.56 keys, 0.23 values).

## MiniCache — SLERP-based cross-layer compression

Each token row in two adjacent layers is decomposed into magnitude and unit direction; the two directions are spherically interpolated into one shared direction, with only the cheap per-layer scalar magnitudes kept separate. Near-parallel vectors fall back to linear interpolation — SLERP's own mathematical limit as the angle between them approaches zero, not an ad hoc guard.

This method got the most disclosed findings of the five, none of them algorithm bugs — all measurement-honesty gaps. First, its own compression ratio: under the exact mechanism specified (one shared direction array plus two magnitude arrays, replacing two full tensors at equal precision), the achievable ratio is `2C / (C+2)` for channel count `C` — it asymptotically approaches but never reaches 2x, short of CAG.md's stated "~2-3x." Not a bug; a structural property of pure cross-layer sharing without also quantizing the magnitudes, disclosed rather than smoothed over. Second, the integration test's own assertion: an earlier version only bounded `max_abs_diff < 40.0` with no top-token check, unlike every other test in the file. A deliberately injected bug (sign-flipping the reconstructed direction — the exact code path the near-parallel fallback guards against) measured 17.2 and *did* flip the model's actual predicted token, yet sailed under the 40.0 bound with room to spare — looser than even this file's own negative-control test needed (~24.5) to prove gross corruption detectable. Fixed by adding the top-token assertion every sibling test already had (the real, correct implementation preserves it, at ~8.57 measured diff) and tightening the bound to 15.0.

## ShadowKV — composing PALU's low-rank step with real sparsity and quantization

Composes `PALUCompressor` directly (a real dependency, not a reimplementation — the same pattern `ConsolidateProcedures` used composing `RecordProcedure` in MAG) for the low-rank step, then layers real magnitude-based sparsity (drop the smallest fraction of the low-rank latent's entries, keep a genuine sparse COO-style representation) and real uniform quantization of the survivors on top. Measured 5.12x on a 32×32 synthetic tensor — meaningfully beyond PALU's own ~4x alone, in the neighborhood of CAG.md's stated ~6x though not an exact match, an honest number from stacking three real mechanisms rather than one tuned to hit the source figure.

## Validated against a real model, not just synthetic tensors

A real `distilgpt2` forward pass (CPU, no GPU needed) extracts an entire layer's real key or value tensor — all 12 attention heads flattened together, 768 channels — compresses and decompresses it through each method, splices the reconstruction back into a fresh copy of the real cache, and confirms a real continuation still predicts the same top token the uncompressed baseline does. An earlier version of this test spliced only one of the 12 heads; review caught that this diluted even *total* corruption of that head below what the assertions could detect, through multi-head attention's own concatenation, output projection, and residual stream — confirmed empirically (zeroing, injecting noise, or reversing an entire head's key tensor left the top token unchanged, max diff under 0.5). Rewritten to splice the full layer, with a negative-control test proving the methodology can actually detect real corruption (a full-layer garbage splice changes the top token and produces a ~24.5 max diff).

Real measured numbers, every method preserving the top token at genuinely lossy fidelity settings (rank=8, comfortably below the real prompt's 15-token ceiling): keys — KIVI 0.0021, KVQuant 0.0000, PALU 0.5618, ShadowKV 0.5537; values — KIVI 0.0059, KVQuant 0.0000, PALU 0.2325, ShadowKV 0.2655; MiniCache (both full layers) 8.5656.

## What two full review rounds caught

**Round one** (four dimensions) confirmed 8 of 8 raw findings: the KIVI and KVQuant axis-fidelity gaps described above; the single-head splice dilution and keys-only test coverage in the integration test; `OVERVIEW.md`'s build-status paragraph left stale after this batch's own additions (the same drift Batch A's own review caught and fixed once already, recurring because this batch's diff never touched `docs/`); `numpy`'s explicit-dependency precedent not extended to the integration test's own direct `torch`/`transformers` imports; `ShadowKVCompressor` exposing one constructor argument (`bits`) as a public attribute while every sibling kept its equivalent state private, solely to serve one test's convenience; and `CompressedKV.payload`'s `dict[str, Any]` typing leaving five compressors' key usage completely unchecked by `mypy --strict`.

**Round two** (a scoped re-review of round one's own fix wave) confirmed 4 of 4 raw findings, three of them defects the fix wave's own new code introduced or left exposed: the KIVI zero-point hybrid-axis gap described above (found by planting a mutation directly and confirming it slipped past the very test written to catch axis bugs); the MiniCache missing-top-token-assertion gap (found by planting a real, plausible bug and confirming it slipped past the widened tolerance bound); and the PALU/ShadowKV rank-clamping-to-lossless gap (found by tokenizing the actual integration-test prompt and confirming the "raised for higher fidelity" rank silently exceeded the real ceiling). The fourth — the `transformers>=4.40` floor being satisfiable by versions lacking the `DynamicCache.layers` API the integration test requires — was verified by diffing `cache_utils.py` across tagged releases to find the exact version (`4.54.0`) that introduced it.

## What this batch does not do

- **Does not implement Eviction** — a separate, deferred (GPU-dependent) technique; this batch compresses what eviction would have left behind, not what eviction removes.
- **Does not implement a serving-time compression selection policy** — choosing which method to apply, when, under what memory pressure, is Cache-Aware Batching's or a future orchestration concern.
- **Does not attempt bit-exact reproduction of any paper's published benchmark numbers** — CAG.md's own figures are architecture-level approximations, and this batch's tensors, model, and parameter choices are its own disclosed choices.
- **Does not require GPU or vLLM** — real CPU tensors from a real small model were sufficient to honestly measure both synthetic and real-model compression fidelity for all five methods.
