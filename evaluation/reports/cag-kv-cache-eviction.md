# CAG Batch C: KV Cache Eviction — Live Measurement Report

**Scope:** #29 (story), #89 (H2O), #91 (SnapKV), #92 (NACL), #93 (MorphKV), #95 (HASHEVICT), #96 (InfiniPot) — six distinct eviction algorithms. See `docs/superpowers/specs/2026-09-06-cag-kv-cache-eviction-design.md` for the design and for why this batch, like Compression and Speculative Decoding before it, doesn't need GPU or vLLM to measure honestly — a claim CAG.md, `CONTEXT_GRAPH.md`, and `OVERVIEW.md` all stated incorrectly for Eviction specifically until this batch corrected it.

## What CAG.md asks for, and what this batch built

Six methods, all deciding which tokens' KV pairs stay resident during decoding rather than shrinking what survives (that's Compression's job, already built and measured): H2O and SnapKV (attention-score-based, differing in how the score is computed), NACL (single-shot proxy scoring plus randomness), MorphKV (recent-pattern Sum/Max Fusion), HASHEVICT (vector-similarity hashing, no attention needed), and InfiniPot (whole-cache distillation rather than per-token selection). Three ports (`KVCacheEvictor`, `RecentPatternEvictor`, `HashBasedEvictor`) plus one distinct shape (`CacheDistiller`) reflect the real differences in what each algorithm consumes — a single score vector, several recent-window score vectors, raw KV vectors, or the whole cache — rather than forcing six genuinely different mechanisms behind one signature.

## H2O — the heavy-hitter baseline

Real accumulated-attention scoring: a fixed recent window is kept unconditionally, and the rest of the token budget goes to whichever older tokens accumulated the most attention mass. Measured against a real `distilgpt2` forward pass (15-token prompt, budget of 7 — roughly half): **0.6631 retained attention mass**, against **0.5393** for random eviction at the identical budget — H2O's own value proposition, that heavy-hitter selection beats picking indices at random, holds up under a real measurement, not just intuition. Memory reduction: 2.14x (15 → 7 tokens). The reduced cache, spliced back across every layer, still predicted the same top token as the uncompressed baseline (`' then'`), though the max logit difference (15.67) confirms eviction is measurably lossier than Compression's own near-zero-diff results — expected, since real tokens are discarded outright here rather than reconstructed from a compressed representation.

## SnapKV — pooled importance, spread to neighbors

Applies real 1D max-pooling (kernel size 3) over the attention-score vector before the same recent-window-plus-top-up selection H2O uses, so a token beside an important one inherits some of that importance rather than needing its own high score. On this batch's real 15-token measurement, SnapKV's pooled selection happened to choose the identical kept set H2O did (retained mass 0.6631, same top token preserved) — disclosed rather than smoothed over: with this particular prompt's attention distribution and a kernel size of 3, the pooling step didn't change which tokens ranked highest. A synthetic unit test (`test_pooling_spreads_importance_to_a_high_scorers_immediate_neighbors`) confirms the pooling mechanism itself does change the selected set when a sharp, isolated attention spike is deliberately constructed — the real-model measurement's convergence with H2O is a property of this specific prompt, not evidence the pooling step is inert.

## NACL — single-shot scoring plus disclosed randomness

Modeled as: most of the budget goes to the top-scoring tokens deterministically, with a `random_fraction` slice instead filled by a seeded random draw from the remaining pool — random_fraction=0.0 degrades to plain top-k, verified directly by a unit test. At random_fraction=0.2 on the real 15-token measurement: **0.7050 retained attention mass**, the highest of the three attention-score-based methods measured here, though this is not a fair apples-to-apples comparison with H2O and SnapKV — NACL has no reserved recent window, so at this budget it simply keeps more of the raw top-scoring tokens outright, with only a small slice replaced by chance. Max logit difference (7.29) was lower than H2O/SnapKV's, and the top token was still preserved.

## MorphKV — Sum/Max Fusion over recent patterns

`fused[i] = sum(window[i] for window in recent_windows) + max(window[i] for window in recent_windows)`, keeping the top-`budget` fused scores — a direct, disclosed reading of "Sum/Max Fusion" with no further reweighting invented on top. Verified against a hand-constructed two-window synthetic fixture where the fused ranking is independently computable (`test_sum_max_fusion_picks_the_indices_with_the_highest_combined_score`); not included in the real-model integration measurement above because it needs multiple real per-step attention snapshots rather than the single full-sequence causal matrix the other three attention-score methods share — a genuine input-shape difference, not an oversight, reflected in its own `RecentPatternEvictor` port.

## HASHEVICT — similarity before attention ever runs

Real SimHash: a fixed set of random hyperplanes (seeded for determinism) turns each raw KV vector into a bucket id; only the most recent occurrence per bucket survives as non-redundant, with a further recency-based trim if deduplication alone overshoots the budget. Two of this algorithm's unit tests exploit a genuine mathematical guarantee rather than probabilistic luck: identical vectors are *provably* bucketed identically regardless of which random hyperplanes were drawn (their dot product against any hyperplane is identical), and antipodal vectors (`a` and `-a`) are *provably* bucketed into exact bitwise complements — both confirmed by an actual run, not assumed from the math alone. Not included in the real-model integration measurement above because it needs raw KV vectors rather than attention scores, and this batch's real-model harness extracts attention weights, not per-token key vectors, for its measured comparison — a scope boundary disclosed here rather than silently left untested at the unit level.

## InfiniPot — distillation, not selection

Partitions an overflowing cache into `budget` contiguous, near-even groups and replaces each with its centroid — the source's own CaP/NuC metrics aren't reimplemented bit-for-bit (no published formula to match against, the same disclosed-choice position ShadowKV and MiniCache already took in the Compression batch); what's built is a real instance of the same structural idea, whole-cache compaction rather than per-token selection. Measured against the real `distilgpt2` cache, distilling all 6 layers' keys and values from 15 tokens down to 5 centroids each: the model still produced a finite, coherent top-token prediction (`' and'`) rather than garbage — the lighter bar this technique is held to, since a centroid isn't any original token's real vector and top-token-match-to-baseline isn't a meaningful comparison for it the way it is for the five index-selecting methods.

## Validated against a real model, not just synthetic data

A real `distilgpt2` forward pass (CPU, no GPU needed) with `output_attentions=True` (requires `attn_implementation="eager"` — the transformers default, SDPA, returns no attention weights at all) extracts the real causal attention matrix, computes real accumulated attention scores via `accumulate_attention_scores`, and reduces every layer's keys and values to the identical kept positions — not just one layer, since eviction changes sequence length and a per-layer mismatch would break attention across layers. H2O's real retained-mass advantage over random eviction (0.6631 vs. 0.5393) is this batch's central live-measured claim; all three index-selecting methods tested against the real model (H2O, SnapKV, NACL) preserved the baseline's real top-predicted token at a 2.14x memory reduction.

## What this batch does not do

- **Does not assert top-token preservation as a pass/fail bar** — eviction is a lossier operation than compression by design; the integration tests measure and report real numbers (retained mass, memory reduction, logit diff) rather than forcing the near-lossless bar Compression held itself to.
- **Does not implement a serving-time eviction selection policy** — choosing which algorithm to apply, when, under what memory pressure, is Cache-Aware Batching's or a future orchestration concern.
- **Does not attempt bit-exact reproduction of any paper's published benchmark numbers** — CAG.md's own descriptions are architecture-level, and this batch's specific interpretations (NACL's random-fraction model, MorphKV's Sum/Max Fusion formula, InfiniPot's centroid distillation in place of CaP/NuC) are its own disclosed choices.
- **Does not require GPU or vLLM** — the same real, CPU-only, real-forward-pass measurement standard Compression and Speculative Decoding already met, correcting CAG.md's prior claim that Eviction specifically needed GPU/vLLM serving to measure honestly.
